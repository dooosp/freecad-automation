# Studio 업그레이드 사용자 테스트 진행 안내

이 안내는 2026-09-30 Studio 개선 이후의 **새 후보 버전**을 위한 진행자용 준비 문서입니다. 기존 Round 1 후보와 결과를 덮어쓰지 않습니다. 실제 참가자 기록이 들어오기 전에는 사람 대상 검증을 `NOT_RUN`, 성공률·소요 시간·이해도를 `NOT_MEASURED`로 유지합니다.

상세 절차, 동의·기록 보관, 공통 과제와 채점 규칙은 [기존 세션 키트](studio-beginner-uat-session-kit.md)를 사용합니다. 아래의 새 라운드 이름과 후보 고정 절차를 적용하고, 키트의 `round-1` 저장 경로를 그대로 재사용하지 마세요.

## 시작 전 준비

1. 해당 개선 PR이 병합되고 자동 검증이 통과한 뒤, 병합 커밋 SHA를 한 번만 확인합니다.
2. 그 SHA에서 깨끗한 detached worktree를 만듭니다. 버전·Git tree·전체 소스 해시를 [키트의 후보 고정 절차](studio-beginner-uat-session-kit.md#freeze-and-preflight-the-candidate)로 기록합니다.
3. 새 라운드 ID는 `studio-upgrade-2026-09-30`으로 둡니다. 이전 라운드의 후보, 실행 기록, 참가자 저장소를 재사용하지 않습니다.
4. 같은 후보에서 기술 리허설 P0와 사람의 한국어/영어 의미 검토를 마칩니다. 자동 번역 키 검사나 AI 검토로 사람의 의미 검토를 통과 처리하지 않습니다.
5. Studio를 사용한 적 없는 참가자 5명을 확보합니다. 진행자의 연습이나 기존 사용자의 피드백은 별도로 기록하며 5명 집계에 넣지 않습니다.
6. 각 참가자에게 익명 기록 동의를 받고, 키트의 분리된 세션·작업 저장소·기록 양식을 준비합니다. 원시 참가자 기록과 작업 저장소는 키트에 정한 비공개 위치에만 보관합니다. 저장소에는 집계 결과만 반영합니다.

후보 SHA나 소스가 바뀌면 새로 고정하고 리허설해야 합니다. 참가자 테스트가 시작된 뒤 변경되면 해당 라운드를 중단하고 5명 모두 같은 후보로 다시 진행합니다.

## 사용할 자료

| 용도 | 자료 | 구분 |
| --- | --- | --- |
| 첫 모델·도면·보고서 | `configs/examples/quality_pass_bracket.toml` | 추천 시작 예제 |
| CAD 가져오기 | `docs/examples/quality-pass-bracket/cad/quality_pass_bracket.step` | 저장소의 합성 STEP |
| 이전 결과 다시 열기 | 별도로 생성한 브래킷 보고서 | 모델 과제 성공 여부와 독립적으로 준비 |
| 실행 완료와 품질 실패 구분 | `configs/examples/ks_bracket.toml`의 사전 생성 보고서 | 의도된 주의 사례; 추천 시작 예제로 안내하지 않음 |

추천 목록의 힌지 블록은 선택지 탐색에서 관찰할 수 있습니다. PCB 장착판은 새 엄격 도면 검사에서 실패했으므로 추천 목록에 포함하지 않고 고급 목록에 유지합니다. 고정 채점 과제 1은 계속 브래킷을 사용하므로 참가자마다 형상 난이도가 달라지지 않습니다. 미리보기, 저장된 실행, 실제 제작 적합성은 서로 다른 판단입니다.

## 참가자에게 읽어줄 과제

상세 완료 조건과 영어 과제는 [공통 과제 카드](studio-beginner-uat-session-kit.md#verbatim-bilingual-task-cards)에 있습니다. 경로나 버튼 이름을 미리 알려주지 않습니다.

1. **모델:** Studio의 `quality_pass_bracket` 예제를 사용해 모델을 만들고 3D 결과를 여세요.
2. **도면과 보고서:** 방금 만든 모델에서 도면을 찾아 확인한 다음, 그 모델의 보고서를 만드세요.
3. **다시 열기:** 이전 작업에서 완료된 브래킷 보고서를 열고 주요 결과를 확인하세요.
4. **가져오기:** 제공된 CAD 파일을 검토하고 검토 결과를 여세요.
5. **문제 이해:** 주의가 필요한 준비된 `ks_bracket` 실행을 열고, 준비되지 않은 이유와 안전한 복구 방법을 설명하세요.

각 과제의 제한은 10분입니다. 과제 1·3·4의 지정된 8개 동작 직전에 “이 동작을 선택하면 무엇이 일어날 것 같나요?”라고 묻고, 답을 먼저 기록합니다. 도달하지 못한 동작도 분모에 포함해 전체 40개를 유지합니다.

## 이번 개선을 확인하는 추가 관찰

추가 관찰은 기존 성공률·40개 예측 채점을 바꾸지 않습니다.

- 추천 예제 이름과 예상 결과가 이해되는지, 전체 예제로 가는 길을 찾는지.
- “실행 완료”와 “품질 실패/경고”를 구별하는지.
- 키보드로 도면 치수를 찾아 편집하고 Escape로 취소한 뒤 위치를 잃지 않는지.
- 실행 모니터와 고급 메뉴를 열고 닫은 뒤 계속 작업할 위치가 분명한지.
- 새로고침이나 다른 작업의 완료가 현재 선택한 화면을 방해하는지.
- 실제 브라우저 200% 확대, 운영체제 동작 줄이기 설정, 필요 시 화면 읽기 도구를 사용했을 때 막히는 지점이 있는지.

## 완료 기준과 기록

| 기준 | 통과 조건 |
| --- | --- |
| UAT-01 | 신규 사용자 5명 중 4명 이상이 도움 요청·진행자 안내 없이 첫 3D 결과를 엶 |

| UAT-03 | 지정된 다음 동작 예측 40개 중 32개 이상 정확 |

미완료 세션, 동의 철회, 진행자가 예측 질문을 빠뜨린 경우의 처리는 공통 키트의 규칙을 따릅니다. 아래 집계 양식은 **빈 양식**이며 실제 측정 결과가 아닙니다.

```text
라운드: studio-upgrade-2026-09-30
후보 SHA / Git tree / 소스 해시: NOT_PINNED
P0 기술 리허설: NOT_RUN
사람의 한영 의미 검토: NOT_RUN
유효한 신규 참가자 기록: 0/5
UAT-01: NOT_MEASURED
UAT-02: NOT_MEASURED
UAT-03: NOT_MEASURED
추가 접근성 관찰: NOT_MEASURED
판정: FOLLOW_UP_REQUIRED
```

참가자가 지금 없다면 후보와 P0 결과까지만 준비해 전달합니다. 사용자 본인이 먼저 사용해 본 피드백도 개선에는 유용하지만, 신규 사용자 5명 결과로 대체하지 않습니다.
