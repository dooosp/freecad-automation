# 90초 시연 대본 — 한국어

- 대상: 채용 담당자, 비개발자, 첫 방문자
- 사람 UAT: `NOT_RUN`
- 스크린샷/P0 상태: [캡처 목록](screenshots/README.md)에서 확인
- 원칙: 화면에서 실제로 확인된 상태만 말한다.

## 사전 준비

Review 화면의 `제조 로봇 데이터` 카드가 실행 전 상태인지 확인한다. 성공
작업과 mismatch 작업은 새로 실행하며, 개인 경로·job ID·터미널은 녹화하지
않는다. 언어는 한국어로 둔다.

## 00:00–00:15 — 문제

**화면:** 실행 전 카드.

**말하기:**

“CAD와 로봇 데이터가 따로 있으면 비개발자는 설계 형상이 어떤 검사 동작과
품질 기준으로 이어지는지 보기 어렵습니다. 이 화면은 승인된 합성 힌지 블록
프로필을 열 개 제조 동작과 역할별 인계로 설명합니다.”

## 00:15–00:30 — 안전한 실행

**조작:** `데이터셋 생성`을 누른다.

**말하기:**

“브라우저는 파일이나 경로를 받지 않고 서버 소유 프로필만 요청합니다. 생성은
로컬·오프라인이고 FreeCAD, 로봇 하드웨어, 외부 또는 유료 API를 호출하지
않습니다. 결과는 작업 디렉터리에만 기록됩니다.”

## 00:30–00:50 — 설계·로봇·품질 연결

**화면:** 성공 요약과 열 개 동작. 6번 `probe_left_hinge_pin`을 선택한다.

**말하기:**

“열 개 동작은 단순 label이 아닙니다. 예를 들어 왼쪽 힌지 핀 검사는 CAD
feature, 품질 특성, 실제 6축 관절 ID, 한·영 지시, 전제·사후 조건으로
연결됩니다. 화면의 `VALID SYNTHETIC DEMO`는 이 합성 계약의 참조와 계보가
유효하다는 뜻입니다.”

## 00:50–01:05 — 인계와 표준 gap

**화면:** Handoff와 LeRobot gap.

**말하기:**

“Design, Manufacturing, Quality, Trust가 각자 확인할 내용을 분리했습니다.
다만 현재 결과는 의미 주석 계층입니다. 프레임별 state/action, FPS, Parquet,
통계와 실제 loader 검증이 없어 LeRobot 호환과 학습 준비는 모두 false입니다.
이미지나 MP4 부재는 이 검사 시나리오의 vision gap이지 모든 v3 데이터셋의
보편 필수 조건이라고 주장하지 않습니다.”

## 01:05–01:22 — 실패가 보여 주는 신뢰

**조작:** 승인된 Revision mismatch 옵션을 켜고 다시 생성한다.

**말하기:**

“Revision A를 기대했는데 B 검토 자료가 들어오면 시스템은
`REVISION_LINEAGE_IDENTITY_MISMATCH`로 차단하고 여덟 파일 중 하나도 게시하지
않습니다. 받은 B를 임의 승인하지 않고, 권위 있는 A에서 검토 자료를 다시
만드는 조치를 제시합니다.”

## 01:22–01:30 — 마무리

**말하기:**

“이 데모가 증명하는 것은 합성 입력의 추적 가능성과 안전한 게시·차단입니다.
실제 현장 데이터, 물리 검사, CV, 생산 승인이나 사람 수용성은 아직 증명하지
않았습니다. 다음 단계는 사람 한·영 의미 검토와 준비된 5명 UAT입니다.”
