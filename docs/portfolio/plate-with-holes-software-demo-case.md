# Plate With Holes Software/Demo Case Study

## Summary

`plate-with-holes` is a compact PCB mount plate CAD and manufacturing review automation demo. It packages a FreeCAD-backed plate model, generated drawing intent, deterministic quality and review artifacts, readiness gating, standard-document drafts, release metadata, and local software/demo closeout material into one reviewable software milestone. This is a software/demo closeout only; it is not a production release or inspection completion claim.

## Problem

Simple CAD examples can overstate their maturity because a generated model, drawing, readiness report, release bundle, and demo UI look complete. This case shows the opposite discipline: the package keeps generated review material useful while preserving the unresolved `inspection_evidence` gap.

## What Was Built

- A curated `pcb_mount_plate` package with AL6061 machining context, plate geometry, four-hole pattern intent, connector slot intent, standoff intent, required drawing views, and manufacturing notes.
- Checked-in canonical package artifacts under [`docs/examples/plate-with-holes/`](../examples/plate-with-holes/README.md), including CAD exports, drawing assets, quality summaries, `review_pack.json`, `readiness_report.json`, standard-document drafts, release metadata, and a small curated release bundle.
- A read-only Studio/package-review path that can surface the package card, source readiness values, safe text previews, and the release-bundle boundary.
- Local ignored software/demo closeout, portfolio, and interview-demo packs generated by `fcad closeout-package` for presentation support.

## Verified Capabilities

- The create-quality sidecar reports `pass` for the checked-in STEP/STL round-trip package evidence.
- The drawing-quality sidecar reports `pass` with score `86`.
- The review pack records four prioritized review topics led by slenderness, complexity, stress/tooling, and wall-thickness review.
- Package quality and drawing side inputs are linked as review evidence and clear the generated `quality_evidence` gap.
- The closeout-package workflow can generate local software/demo closeout material for this package with `--strict-boundary` while leaving checked-in canonical artifacts read-only.
- The `release_bundle.zip` file is transport/review material, not readiness proof.

## Demo Path

Generate ignored local software/demo closeout material from the checked-in package:

```bash
node bin/fcad.js closeout-package plate-with-holes --mode software-demo --out-dir output/plate-with-holes-closeout --strict-boundary
```

Review the generated local closeout, portfolio draft, and interview talking points as presentation material only. Do not commit generated `output/` artifacts.

For the browser review path, run the local Studio server:

```bash
node bin/fcad.js serve 3100 --jobs-dir output/jobs-studio-demo
```

Open:

```text
http://127.0.0.1:3100/studio
```

Review the canonical `plate-with-holes` package card, readiness fields, safe artifact previews, release-bundle ZIP boundary, and missing `inspection_evidence` signal.

## Readiness Truth

The source-of-truth readiness state from [`docs/examples/plate-with-holes/readiness/readiness_report.json`](../examples/plate-with-holes/readiness/readiness_report.json) is:

| Field | Value |
| --- | --- |
| Readiness status | `needs_more_evidence` |
| Score | `61` |
| Gate decision | `hold_for_evidence_completion` |
| Missing input | `inspection_evidence` |
| Production-ready | no |

The review source is [`docs/examples/plate-with-holes/review/review_pack.json`](../examples/plate-with-holes/review/review_pack.json). Its uncertainty coverage keeps `inspection_evidence` missing even though package quality and drawing evidence are linked.

## Evidence Boundary

This is software/demo closeout only. No physical part inspection was completed or attached. No supplier inspection, no lab inspection, no CMM inspection, no manual caliper inspection, no gauge inspection, and no first-article evidence was completed or attached.

Generated CAD, drawing, quality, review, readiness, standard-doc, release, Studio, portfolio, and closeout artifacts are review/demo evidence only, not inspection evidence. CAD-derived nominal or reference values are planning context, not physical measurements. Screenshots, generated reports, readiness reports, standard-document drafts, release bundles, closeout packs, and CI summaries are not inspection evidence.

Production readiness remains held until genuine completed `inspection_evidence` is attached through the canonical flow and the review, readiness, standard-doc, and release chain is deliberately regenerated. The release bundle is transport/review material, not readiness proof.

## Portfolio Value

This case is useful because it shows a small package moving through the same honest evidence gate as larger examples:

- It demonstrates a reusable closeout workflow across a second canonical package.
- It keeps generated package quality and drawing evidence separate from physical inspection evidence.
- It exposes why a score of `61` and passed generated quality checks still do not make the package production-ready.
- It gives a bounded future Stage 5B path without pretending that Stage 5B happened.

## Future Work

Future Stage 5B requires genuine completed inspection evidence from a physical part, supplier-inspected part, or lab-inspected part. Only then should the team validate the inspection evidence JSON, attach it through the explicit review-context path, and regenerate the canonical review, readiness, standard-doc, and release artifacts.
