4번에서는 모델 길이도 150과 142로 각각 바꾸어 Studio에서 STEP을 만들었다. 기본 FreeCAD 표준 API로 복사한 FCStd의 길이를 바꾸고 저장·재열기한 결과와 비교했다. 두 길이 모두 유효 솔리드 1개, 외곽·두께·구멍 좌표 일치, 두 방식의 대칭 차집합 부피 0 mm³였다. 복원한 142 형상과 원래 REV B의 차이도 0 mm³였다. 주석 변경으로 모델 형상이 바뀌었다고 기록하지 않았다.

입력 오류·통신 실패·취소 경합은 실제 브라우저와 별도 시험 서버에서 확인했다. 작업이 시작되기 전 취소 성공 경로는 제어된 실행기를 사용한 테스트로 검증했으며, 실행 중인 FreeCAD 명령을 강제 중단하지 않았다. 입력 선택기와 기본 FreeCAD GUI는 도구·환경 제약이 있어 성공했다고 기록하지 않는다. 파일 재열기는 실제 FreeCAD 표준 API로 검증한다.

8번의 실제 반복 중에는 자동 치수 값이 SVG 뒤쪽에 있으면 QA에서 빠지던 기존 문제도 고쳤다. 동일 실제 FreeCAD 회귀 도면에서 필수 치수 누락이 1→0, QA가 80→90으로 바뀌었고, 기존에 실패하던 런타임 회귀 두 건을 포함한 네 검사가 통과했다.

최종 통합 검토에서는 도면 수정 응답을 기다리는 동안 화면을 다시 만들면 적용 버튼이 비활성으로 남고 이력의 현재 위치가 덮어써지는 문제를 추가로 발견했다. 공유 이력을 기준으로 동기화하고 현재 화면에 완료를 알리도록 고쳤다. 실제 브라우저에서 142→150 적용 대기 중 한글→영어, 실행 취소 대기 중 영어→한글을 수행했다. 추가 조작 없이 버튼·치수·이력이 갱신됐다. 다시 실행 후 모델→도면 왕복에서도 150과 적용 이력을 유지했고, 마지막에 142로 복원했다. 응답이 대기 중인 다시 실행·실패 경로는 제어된 회귀 검사로 별도 확인했다. 추가 수정 커밋: `56189b5`.

검증 결과:

- `npm test`: 계약·통합·스냅샷 모두 통과. 마지막 이력 수정은 관련 검사 62개와 실제 브라우저 재시험, 독립 검토로 추가 확인했다.
- 커밋 `e0039f2`의 깨끗한 분리 작업 트리에서 `npm run test:py`: 172개와 하위 검사 27개 통과. 생성 SVG가 필요한 1개는 실제 FreeCAD 도면을 만든 뒤 별도 실행하여 통과했다. 마지막 이력 수정은 브라우저 JavaScript와 Node 검사만 변경했다.
- 기본 Python 명령에서 제외하는 실제 런타임 회귀 검사 세 파일: 총 4개 통과. 런타임 smoke, 소스 산출물 위치 검사, 최종 여섯 축척 조건, AUTO 엄격 검사도 통과했다. 여섯 축척 조건 중 요청한 축척을 지키지 못하는 한 조건은 의도한 엄격 실패를 확인한 것이다.
- Console·Review·Packs·Model·Drawing을 실제 브라우저에서 순회했다. 수정된 검토·패키지 화면을 한·영으로 확인했고, 1280 px 창에서 가로 넘침·타임라인 버튼 겹침이 없었다.
- 원래 작업 폴더의 전체 Python 검사는 별도 작업인 미추적 `docs/superpowers/` 문서의 기기 절대 경로 때문에 1개 실패했다. 해당 문서와 검사는 수정하지 않았으며, 위 분리된 커밋 소스 검사로 구분했다.
- 기준 커밋 `82f7a17` 포함을 다시 확인했고, 기존 A/B 원본 16개 SHA-256은 전부 유지됐다.

QA 점수는 모델과 모든 주석의 일치를 보증하지 않는다. 최종 AUTO 도면에서 계획 주석을 150으로 바꾸면 자동 치수 142와 함께 표시되면서 점수는 89였다. 현재 숫자 일치 검사는 계획과 SVG를 비교하므로, 형상 치수·근거 연결·엄격 품질 판정은 별도로 확인해야 한다. 앞선 단계의 점수 66을 일반적인 형상 불일치 차단 기능으로 해석하지 않는다.

실물 필요·USB 허브 모델·실측값·재료·체결 간격·장착 안정성은 미확인이다. 실제 제작·장착 승인은 내리지 않았다. 기본 FreeCAD와 Automation의 형상 결과를 비교했지만 이번 추가 점검으로 사람의 작업 시간 절감률을 계산하지 않았다. 네이티브 파일 선택기와 외부 STEP 앱 열기는 완료하지 못했고, 내장 PDF 뷰어도 사용할 수 없었다. 실제 다운로드 파일의 FreeCAD 재열기, PDF 렌더링·텍스트 추출 결과로 검증 범위를 명시했다.

다음 점검은 실제 허브와 설치 위치의 실측값을 받은 뒤 간섭·여유·체결을 확인하는 것이다. 네이티브 파일 열기 동작은 조작 도구가 사용 가능한 환경에서 추가 확인할 수 있다. 이번 여덟 항목에서 재현한 수정 사항은 단계별로 커밋·푸시했으며, 사용한 브랜치는 `codex/mega-studio-api-contract-fuzz-audit`다.
