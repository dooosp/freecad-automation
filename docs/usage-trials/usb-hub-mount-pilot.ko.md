# 첫 실사용 권장안: 책상 옆 USB 허브 고정용 어댑터판

작성일: 2026-09-12. 상태: **대상과 실측값을 확인하기 전의 권장안**. 이 문서 작성으로 실제 부품 설계나 사용성 검증이 완료된 것은 아니다.

**추천하는 작업은 태호가 이미 사용하는 USB 허브를 원하는 위치에 고정하기 위한 맞춤 평판 하나를 설계하고 수정하는 것이다.** 케이블을 꽂을 때 허브가 움직이거나, 포트에 손이 닿기 어렵거나, 기존 고정점과 원하는 위치가 맞지 않는 불편이 있을 때 시작한다.

## 1. 이 부품을 고르는 이유와 시작 조건

- 태호가 연결·분리 동작을 직접 해보며 포트 접근성과 배치의 유용함을 판단할 수 있다.
- 허브 위치나 고정점이 바뀌면, 구멍 위치·판 외곽·도면 갱신을 다시 확인하는 작업이 생길 수 있다.
- 실제 요구가 평판으로 해결된다면, 최근 확인한 모델 생성·도면·치수 근거 연결 흐름을 사용할 수 있다.

먼저 **허브가 실제로 있고, 현재 불편이 있고, 맞춤판이 필요한 이유가 있는지** 확인한다. 보유한 벨크로나 기본 브래킷으로 충분히 해결된다면 그 방법을 선택하고 CAD 제작은 생략한다. 허브가 없으면 실제로 고정이 필요한 작은 물건을 태호에게 확인한다. 그런 필요도 없으면 현재 버전을 보존하고 시험을 보류한다.

목표는 태호의 물건과 설치 위치에 맞는 모델·도면·변경 기록을 얻는 것이다. 첫 회차의 완료 범위는 설계와 사용 비교이며, 실물 제작 여부는 그 결과로 판단한다.

## 2. 무엇을 설계할 것인가

제안 형상은 **설치면과 허브 고정부를 연결하는 평판 한 개**다. 허브 쪽 고정과 책상 쪽 고정을 따로 정의해야 한다.

| 연결 | 먼저 확인할 것 | 설계에 반영할 내용 |
| --- | --- | --- |
| 책상 ↔ 판 | 기존 고정점, 사용할 수 있는 평면, 허용되는 고정 방식 | 판 외곽과 설치 구멍·고정 구역 |
| 판 ↔ 허브 | 실제 장착 귀·구멍 또는 사용할 밴드의 경로 | 허브 위치, 체결 구멍 또는 밴드 통로 |
| 허브 ↔ 케이블·손 | 포트 방향, 꽂힌 커넥터 길이, 손이 들어갈 공간 | 비워둘 영역과 접근 방향 |

허브 본체의 장착 구멍은 실물이나 해당 모델의 제조사 도면에서 확인한다. 구멍이 없는 허브라면 보유한 고정 수단으로 가능한지부터 판단한다. 별도 클램프나 복잡한 받침대를 새로 설계해야 한다면 첫 평판 사례의 범위를 벗어나는 것으로 기록한다.

판의 길이·폭·두께, 구멍 수·지름·좌표는 아직 정하지 않는다. 이전 예제의 `120 × 60 × 3 mm`, `Ø4.5`, `96 → 88 mm`를 가져오지 않는다. 재질·공차·두께의 설계 가정과 실측값을 구분한다.

실제 요구가 장공, 서로 다른 구멍 지름, 많은 구멍 등을 필요로 하면 그 요구를 유지한다. 현재 자동 검증 범위를 벗어난 부분은 미확인과 수동 확인으로 기록한다. 검사를 통과시키려고 구멍 수나 고정 방식을 바꾸지 않는다.

## 4. 다음 세션에서 진행할 순서

1. **환경과 필요 확인.** 저장소·브랜치·커밋·작업 상태를 확인하고, 위 정보를 한 번에 묻는다. 실제 필요가 확인되면 중립적인 `requirements.md`에 기준 모서리·축·실측값·미확인 값을 적는다.
2. **REV A 요구 확정.** 허브의 배치, 두 연결부의 고정 방식, 필요한 치수와 확인 기준을 정한다. 태호가 원하는 결과인지 확인한 뒤 모델을 만든다.
3. **두 방식으로 같은 작업 수행.** 같은 AI와 같은 설치된 FreeCAD를 사용한다. 한쪽은 기본 FreeCAD, 다른 쪽은 FreeCAD Automation을 사용한다. 실행 순서를 시작 전에 정해 기록하고, 공통 측정 비용과 각 방식의 준비 비용을 구분한다.
4. **실제 변경 한 번 적용.** 예를 들어 케이블 접근 때문에 설치 위치를 옮겨야 한다면, 실측에 근거한 이동량을 `change-request.md`에 한 번 정의하고 두 방식에 동일하게 적용한다. 바뀌어야 할 항목과 유지할 항목을 함께 적는다. 실제 변경 필요가 없으면 변경 시험 미수행으로 기록한다.
5. **태호의 확인과 비교.** 모델·도면을 직접 열어 원하는 배치인지, 무엇이 확인됐고 미확인인지 이해되는지 확인한다. 코덱스의 화면 확인을 태호의 확인으로 대신 기록하지 않는다.
6. **이번 사례의 결론.** 계속 사용 / 반복된 불편 한 가지 개선 / 현재 버전 보존 후 개발 종료 / 실제 필요가 없어 보류 중 하나를 근거와 함께 정한다.

실행 중 프로그램의 기능 추가는 보류하고 불편을 모은다. 기본 FreeCAD 쪽에 필요한 모델링·검사 스크립트와 작업용 입력 파일은 작성해도 된다. 잘못된 결과를 통과시키는 문제가 발견되면 해당 결과의 사용을 중단하고 재현 근거를 남긴다.

## 5. 공정하게 비교하는 방법

기본 FreeCAD도 TechDraw에서 모델의 치수를 도면에 표시하고, 모델 변경을 도면에 반영하며, SVG로 내보낼 수 있다. 기본 방식에 이 기능과 Python·매크로·검사 스크립트 사용을 허용한다. [FreeCAD 공식 TechDraw 안내](https://blog.freecad.org/2025/10/10/tutorial-getting-started-with-techdraw/)

| 조건 | 기본 FreeCAD | FreeCAD Automation |
| --- | --- | --- |
| 입력 | 같은 중립 요구사항·실측값·변경 요청 | 동일 |
| 사용 도구 | 같은 AI, FreeCAD, 필요한 자체 스크립트·검사 | 같은 AI, FreeCAD, 현재 프로젝트 |
| 공통 결과 | 재수정 가능한 정의, STEP, 치수가 있는 SVG 도면 | 동일; 프로젝트 보고서는 추가 비용·효용 평가 |
| 비용에 포함 | 스크립트 작성·수정, 파일 관리, 결과 확인 | 설정 준비·관리, 명령 실행, 보고서 해석, 결과 확인 |

기본 방식에 프로젝트 모듈·기존 검사 코드·기존 생성 결과를 가져와 독립 작업인 것처럼 취급하지 않는다. 두 방식이 같은 중립 요구사항과 평가 기준을 공유하는 것은 허용한다. 먼저 수행한 방식의 학습 효과를 기록하고, 한 사례로 일반적인 우위를 주장하지 않는다.

공통 확인 기준은 모델의 판 외곽·두께·구멍 수·지름·중심 좌표가 요구와 맞는지, 도면의 필요한 치수와 리비전이 해당 모델과 일치하는지, REV B에서 의도한 변경과 그에 따른 종속 변경만 생겼는지다. 커넥터 접근성과 실제 장착 가능성은 태호의 확인 항목으로 구분한다. `drawing-quality = pass`는 이 전체 목록의 자동 완료를 뜻하지 않는다.

아래 표를 작업 중 채운다. 사람의 작업 시간은 태호가 직접 기록한 값만 쓰고, 측정하지 않았으면 `미측정`으로 남긴다. 명령 실행 시간과 사람의 회신 대기 시간을 사람의 작업 시간으로 대체하지 않는다.

| 기록 항목 | 기본 FreeCAD | Automation |
| --- | --- | --- |
| 입력·설정·초기 스크립트 준비 시간 | 미측정 | 미측정 |
| REV A 생성·해석·확인에 직접 들인 시간 | 미측정 | 미측정 |
| REV B 수정·재확인에 직접 들인 시간 | 미측정 | 미측정 |
| 사람이 개입한 일과 이유 | 미기록 | 미기록 |
| 발견한 오류, 발견 시점, 재작업 | 미기록 | 미기록 |
| 정상 결과를 막은 경고·불명확한 설명 | 미기록 | 미기록 |
| 수정 후 재사용한 설정·검사 | 미기록 | 미기록 |

## 6. 남길 결과물과 종료 기준

**실제 필요, 실행한 결과, 태호가 확인한 내용, 들인 수고, 다음 결정이 기록되면 첫 시험을 종료한다.** 도움이 반복해서 확인되면 그때 드러난 불편 하나를 개선한다. 개선 목록을 비우는 것을 종료 조건으로 삼지 않는다.
