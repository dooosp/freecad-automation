## What CI Proves

- Hosted CI proves:
  - `npm run check:source-hygiene`
  - `npm run test:node:contract`
  - `npm run test:node:integration`
  - `npm run test:snapshots`
  - `npm run test:studio-browser-smoke`
  - `npm run test:py`
- Hosted CI does not prove a live FreeCAD install or launch on any platform.
- Self-hosted macOS runtime smoke proves:
  - `fcad check-runtime`
  - `fcad create`
  - `fcad draw --bom`
  - `fcad inspect`
  - `fcad fem`
  - `fcad tolerance --recommend --csv`
  - `fcad report`

## What Runtime Smoke Proves

- Runtime smoke proves the repository-owned macOS FreeCAD path works end to end for `check-runtime`, `create`, `draw --bom`, `inspect`, `fem`, narrow `tolerance --recommend --csv`, and `report`.
- Runtime smoke does not prove Linux, Windows native, or WSL -> Windows runtime execution.
- Runtime smoke does not elevate broader tolerance or Monte Carlo maturity to repository-owned CI claims.

## What Is Still Compatibility-Only

- Linux local with FreeCAD installed
- Windows native + FreeCAD 1.1
- WSL -> Windows FreeCAD
- Any hosted CI environment that does not install or launch FreeCAD

## Release Bundle Dry-Run

Use this section to rehearse release-bundle generation without publishing or
mutating checked-in package artifacts.

1. Start and end with source hygiene:

   ```bash
   npm run check:source-hygiene
   npm run release:dry-run:doctor
   npm run check:source-hygiene
   ```

2. Confirm the doctor output stays under ignored `output/release-dry-run-doctor/`.
3. Confirm the doctor report says no tag, GitHub release, artifact upload,
   evidence attachment, Stage 5B promotion, canonical readiness regeneration, or
   checked-in package mutation occurred.
4. Inspect `release_bundle_manifest.json` as the canonical package inventory for
   the dry-run.
5. Inspect `release_bundle_checksums.sha256` as the checksum sidecar for bundle
   entries and `release_bundle_log.json`. It is not a GitHub release asset
   checksum and does not by itself publish or attach anything.
6. Expect `release_bundle_artifact-manifest.json` beside the dry-run bundle as
   ignored CLI artifact-manifest provenance. It can include local runtime/path
   metadata and must not be committed, uploaded as evidence, or attached to a
   GitHub release by automation.
7. Keep dry-run outputs ignored. Do not commit `output/`, `.ci/`,
   `tmp/codex/`, local inbox records, screenshots, CI diagnostics, or generated
   release-publication artifacts.

## Human Publication Steps

Publication remains a human maintainer decision outside automated dry-run work.
Only proceed when maintainers intentionally choose to publish.

1. Confirm the exact `master` commit selected for publication.
2. Confirm the hosted `Automation CI (hosted fast lanes)` status is green for
   that commit, especially the Python lane if it was `BLOCKED BY ENVIRONMENT`
   locally.
3. Confirm the latest relevant `FreeCAD Runtime Smoke (self-hosted macOS)` run
   or local self-hosted rerun matches that commit and includes `fem` plus narrow
   `tolerance --recommend --csv`.
4. Confirm the hosted check names and branch-protection expectations in
   [`docs/ci-governance.md`](../ci-governance.md). Do not change GitHub settings
   as part of release publication unless maintainers explicitly choose to do so.
5. Only after explicit maintainer approval, create and push tag `v1.1.0` from
   `master`.
6. Only after explicit maintainer approval, create the GitHub release using
   [`docs/releases/v1.1.0-draft.md`](./v1.1.0-draft.md) as the release body and
   [`docs/releases/v1.1.0-final-audit.md`](./v1.1.0-final-audit.md) as the
   operator audit reference.
