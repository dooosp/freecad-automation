## Input and result freshness

General reports must match a consumed input snapshot and the exact quality
artifact bytes to their provenance before including them in a current pass.
Historical or unlinked files remain available, but need a fresh create/draw
run (and matching manifests) before reuse as current quality evidence.
Studio full-quality reports collect fresh create/draw results in the current
job. Execution success, quality status, and manufacturing readiness remain
distinct concepts.

This binding covers consumed config bytes and quality/analysis results. It does
not recursively pin the contents of referenced CAD files, drawing plans, URLs,
material definitions, or rule profiles. Regenerate outputs when those change.
CLI `draw --override` cannot prove the base config alone describes the effective
input; its input hash remains unverified for general report reuse. Use a saved
effective config or a fresh Studio full-quality run instead of relabeling old
manifests as current.

URL imports now refresh the source on every import with a 30-second socket
timeout and atomic replacement. If the refresh fails, the old cache bytes are
preserved but are not silently imported. Use an explicit local file path for
offline work.

Revision-bound drawing saves reject stale/missing preview snapshots and require
regeneration. Legacy revisionless fallback must not be used to explain the
current Studio's save guarantee. `review-context` is runtime-conditional when
its model/context includes geometry to inspect, with metadata-only fallback.

The SVG inventory collected during this audit includes checked-in examples,
test fixtures, and separately published portfolio A/B drawings. Being the
latest checked-in file at a branch tip does not mean it was regenerated by
the latest software. The user's Mac-only files and ignored local outputs are
outside this checkout's evidence.
