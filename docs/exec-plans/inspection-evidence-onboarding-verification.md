# Inspection Evidence Onboarding Verification

## Verification objective

Prove that the onboarding contract fails closed, preserves the five canonical
package holds, never promotes synthetic/generated/control artifacts, and keeps
attachment separate from readiness regeneration. No genuine evidence is needed
or fabricated for this verification plan.

## Verification order

1. Record repo, branch, HEAD, default branch, and pre-change canonical package
   readiness/hash facts.
2. Validate every new JSON schema with representative marked synthetic/control
   fixtures.
3. Run focused state-machine, quarantine, validation, authorization, attachment,
   idempotency, and readiness-boundary unit tests.
4. Run adversarial CLI/integration tests.
5. Run existing inspection evidence, readiness, source-hygiene, doctor,
   contract, integration, and no-evidence lanes.
6. Re-hash the five canonical readiness reports and prove their status/gate did
   not change.
7. Perform a skeptical read-only diff review; capture `git diff --name-only`
   immediately before and after and invalidate the review if the diff changes.

## Required adversarial matrix

| Attack/input | Required result |
| --- | --- |
| Generated QIF-lite control XML | Quarantined at most; rejected as generated/control and unsupported QIF |
| STEP/STL/BREP/FCStd, drawings, screenshots, PDFs generated by this repo | Rejected as CAD/drawing/generated content |
| CI logs, workflow artifacts, check summaries, release artifacts | Rejected as CI/control/distribution metadata |
| Synthetic fixture in original path | Rejected by mandatory synthetic marker/content classification |
| Synthetic fixture copied or renamed | Rejected by content marker/fingerprint, independent of path |
| Missing inspector identity/reference | Semantic validation fails |
| Missing reviewer or authorizer provenance | Review/authorization fails |
| Incomplete/pending inspection status | Semantic validation fails |
| Package or revision mismatch | Semantic/authorization validation fails |
| Source/envelope/authorization checksum changed after review | Authorization or attachment fails |
| Exact duplicate attachment | Idempotent no-op returning the original receipt |
| Conflicting duplicate checksum/binding | Fails closed; supersession is deliberately unsupported in this version |
| `..`, absolute output target, NUL/backslash path tricks | Rejected before file access/write |
| Symlink file or directory escape | Rejected after `lstat`/`realpath` containment checks |
| Malformed JSON or CSV, including invalid UTF-8 | Structural validation fails without state promotion |
| Duplicate JSON decision/checksum/synthetic keys | Rejected before last-key-wins parsing can affect trust classification |
| XML/QIF-like input, malformed or well formed | Rejected; no full-QIF support claim |
| `exception`, `override`, `force`, or bypass claims without scoped authorization | Rejected; required gates remain non-waivable |
| Readiness regeneration before attachment | Rejected before any output mutation |
| Attachment command | Does not change readiness artifacts |
| Regular canonical readiness writer racing attachment | Shared package lock rejects one mutation; no mixed JSON/Markdown receipt state |
| Regular canonical readiness writer after attachment | Rejected; separately authorized regeneration is required |
| Noncanonical JSON or derived Markdown symlink/hardlink to canonical readiness | Rejected by realpath/inode checks; canonical bytes remain unchanged |

## Canonical immutability checks

Before and after validation, record SHA-256 plus status/gate/missing inputs for:

- `docs/examples/quality-pass-bracket/readiness/readiness_report.json`
- `docs/examples/plate-with-holes/readiness/readiness_report.json`
- `docs/examples/motor-mount/readiness/readiness_report.json`
- `docs/examples/controller-housing-eol/readiness/readiness_report.json`
- `docs/examples/hinge-block/readiness/readiness_report.json`

Expected invariant for all five:

```text
status = needs_more_evidence
gate_decision = hold_for_evidence_completion
missing_inputs contains inspection_evidence
```

No `inspection_evidence.json`, authorization record, or attachment receipt may
be created under a current canonical package during this task.

## Evidence rules

- record exact commands, exit codes, and relevant artifact hashes
- distinguish a passing synthetic/control rejection test from genuine evidence
  validation; the former never proves a real record exists
- distinguish task-introduced failures from documented pre-existing failures
- redact private paths in versioned artifacts and final user-facing examples
- do not claim full QIF support, runtime-backed physical inspection, production
  readiness, release approval, or successful real attachment
