치수만 바뀌는 부품 작업을 로컬 자동화로 정리합니다. 고객이 합의한 입력, 생성 파일, 검수 근거와 재실행 방법을 하나의 인계 묶음으로 받는 FreeCAD Automation 파일럿입니다.

## 무엇을 받게 되나요

- **실행 환경 설정** · 합의한 macOS 환경에서 FreeCAD와 Node.js 연결을 확인하고, 고객이 직접 쓸 수 있는 소스 폴더를 준비합니다.
- **고객별 입력 설정** · 기존에 지원하는 형상 안에서 부품군 {{part_families}}개와 파라미터 조합 최대 {{max_variants}}개를 정리합니다. 새로운 형상 엔진 개발은 포함하지 않습니다.
- **생성 파일과 검수 근거** · 합의한 조합의 STEP/STL, create-quality JSON, output-manifest, artifact-manifest를 함께 전달합니다.
- **재실행 가능한 인계** · 입력 파일, 실행 명령, 실패 시 확인 방법, 검수 기록을 설명하고 인계 후 정해진 범위의 원격 지원을 제공합니다.

## 이런 업무에서 시작합니다

같은 형태의 브래킷·판재 등에서 치수 조합을 반복해서 바꾸는 업무가 우선 대상입니다. 실제 적용 가능 여부는 부품 형태와 입력 관계를 확인한 뒤 판단합니다. 첫 상담에서 기밀 모델을 공개할 필요는 없습니다.

:::note 소스 이용료는 없습니다. MIT 소스를 직접 설치해 사용할 수 있으며, 파일럿 비용은 환경 설정·고객별 적용·검수·인계·제한된 지원에 대한 비용입니다.

# “만들어졌습니다” 다음에,\n검수할 근거가 남습니다.

파일 존재 여부와 실행 성공만으로 완료를 판단하지 않습니다. 합의한 입력마다 실제 생성 결과와 검증 기록을 함께 확인합니다.

## 01 · 적용 범위 합의

부품군, 파라미터 목록, 허용 범위, 필요한 STEP/STL, 실행 환경을 정합니다. 같은 입력을 다시 실행하는 절차와 고객이 확인할 항목까지 먼저 기록합니다.

## 02 · 환경 설정과 샘플 확인

쓰기 권한이 있는 로컬 소스 체크아웃에서 시작합니다. 환경 확인의 `ready`와 실제 샘플 생성·검증 성공의 `demo_passed`를 구분합니다. 제공되는 브래킷 샘플은 고객 부품 납품 실적이 아닙니다.

## 03 · 고객 입력 적용과 검수

합의한 조합을 생성하고 설정 수정 {{revision_rounds}}회를 범위 안에서 진행합니다. 실패하거나 누락된 조합을 성공으로 합산하지 않습니다. 범위 변경이 필요한 요청은 일정·금액을 별도로 합의합니다.

## 04 · 결과 인계와 지원

재실행 명령과 검수 근거를 함께 인계합니다. 인계 후 {{support_days}}일 안에 총 {{support_hours}}시간의 원격 지원을 제공합니다. 지원 세션은 고객이 요청하고 승인한 경우에만 진행합니다.

## 함께 확인할 완료 기준

- 합의한 입력 조합 각각에서 STEP/STL이 생성되고, 명시적인 strict create-quality 검사를 통과합니다.
- 실제 STEP 재읽기·STL 검사 근거와 매니페스트의 파일 크기·해시를 확인합니다.
- 같은 설정을 별도 출력 폴더에서 두 번 실행합니다. 기존 고객 파일을 덮어쓰지 않고 입력·명령·검수 기록을 인계합니다.

:::note Studio의 작업 성공은 실행 상태입니다. 품질 근거가 없으면 Quality/Ready는 Unknown일 수 있습니다. 이 표시를 품질 통과로 읽지 않으며, strict CLI 검수 결과를 별도로 확인합니다.
