# 수입검사 수정본 비교 파일럿

품질 담당자 2명이 합성 성적서 10건의 최초본과 수정본을 각각 수기 Excel, Claude 제조 기능 또는 CSV 분석, 로컬 `incoming-inspection`으로 검토한다. 판정 단위는 구매자 기준의 **특성 × 필수 표본**이다. 이 파일은 진행자용이다. 검토자에게는 차례가 된 입력과 공통 작업 지시만 전달한다. 현재 수집 상태는 [파일럿 집계표](results/pilot_summary.ko.md)에 있다.

## 진행자 준비

패키지 디렉터리(`packages/incoming-inspection`)에서 Python 3.9 이상으로 실행한다. 첫 명령은 로컬 도구를 독립 정답표와 대조한다. 두 번째 명령은 새 수집 폴더를 만들고 관측값은 모두 비워 둔다.

```sh
python3 benchmarks/scripts/score_benchmark.py --out benchmarks/results/machine.json
python3 benchmarks/scripts/pilot.py prepare benchmarks/results/run-01 --claude planned
```

- **역할**. 두 검토자에게 무작위로 R1과 R2를 부여한다. 제3의 진행자가 독립 정답표와 채점을 담당한다. 이름·회사·고객·실제 공급사 자료를 기록하지 않는다. 외부 전송이 허용된 익명·합성 입력만 Claude 비교에 사용한다. 이 저장소의 10건은 합성 입력이다.
- **자료 지급**. `packets/B01/first/`처럼 번호만 있는 폴더를 한 번에 하나씩 지급한다. 각 폴더의 `intake.json`은 접수 공급사와 로트, `mapping.json`은 동일한 열 대응표다. 모든 방법에 같은 바이트를 제공한다. 수정본과 그 회차의 기준·매핑은 최초본 제출 후에 연다. 사례 설명이 든 원본 폴더명, 저장소, `ground_truth.json`, 채점기, 다른 방법 또는 다른 검토자의 제출물은 지급 대상에서 제외한다.
- **환경 고정**. 시작 전 `environment.json`에 실제 Excel 버전·빌드, 로컬 패키지/규칙 버전, Claude의 모델 식별자와 제조 플러그인·스킬의 이름 및 버전을 적는다. 일반 CSV 분석으로 해당 구성요소를 쓰지 않으면 그 칸에 `not_used`를 적는다. 고정 프롬프트 원문과 SHA-256, 기준·입력·정답표 및 배정표의 지문은 준비 명령이 기록한다. 검토자는 같은 조건의 기기와 비측정 연습 예제로 도구 조작을 익힌다.
- **Claude 확보 여부**. 시험 계획이 있으면 `planned`로 60회를 배정한다. 접근 자체가 불가능하다고 확인하면 `unavailable`로 40회를 배정한다. [시험 불가 확인 양식](templates/claude_unavailable.json)에 확인값, 구체적 사유, 익명 근거 번호를 입력해 `evidence/`에 두고 `claude_unavailable_record`에 상대경로를 적는다. 현장 업무에 오프라인 실행이 필수라고 확인한 비교는 `offline_required`로 40회를 배정할 수 있다. [현장 확인 양식](templates/offline_confirmation.json)을 `evidence/`에 복사해 실제 업무 범위, 익명 근거 번호, 출처 종류(`field_policy` 또는 `field_interview`)와 확인값을 기록하고 `offline_requirement_record`에 상대경로를 적는다. 계정 미보유나 서비스 제한으로 시험이 실제 불가능하다고 확인한 경우에도 현장의 오프라인 필수 여부는 별도로 기록한다.

## 교차 배정

표의 순서는 같은 검토자가 같은 사례를 접하는 회차 순서다. I는 로컬 `incoming-inspection`이다.

| 사례 | R1, 1 → 2 → 3회차 | R2, 1 → 2 → 3회차 |
| --- | --- | --- |
| B01 · B04 · B07 · B10 | Excel → Claude → I | I → Claude → Excel |
| B02 · B05 · B08 | Claude → I → Excel | Excel → I → Claude |
| B03 · B06 · B09 | I → Excel → Claude | Claude → Excel → I |

두 방법만 배정하면 홀수 사례는 R1이 Excel → I, R2가 I → Excel 순서로 진행하고 짝수 사례는 반대로 진행한다. 한 회차 안에서는 R1이 B01부터 B10, R2가 B10부터 B01까지 진행한다. 같은 사례를 다시 보기 전에 다른 사례 아홉 건을 거친다. 매 세션은 빈 통합문서·새 대화·새 출력 폴더에서 시작한다. 최초본과 수정본 사이에는 해당 세션의 최초본 결과만 이어서 사용할 수 있다. 모든 회차가 끝날 때까지 정답과 채점 결과를 공개하지 않는다. 두 명이 같은 사례를 재검토하므로 학습 효과가 남을 수 있다.

## 세션 1회의 기록

검토자 한 명이 한 방법으로 한 사례의 최초본과 수정본을 마치는 것이 1회다. `sessions.csv`에는 방법별 20회가 미리 배정된다. 스톱워치로 구간별 **경과 초**를 기록한다. 파일 열기·도구 실행·응답 대기·해당 결과 저장 시간을 포함한다.

| 구간 | 측정 시작과 종료 | 기록 열 |
| --- | --- | --- |
| ① 최초 매핑 설정 | 동일한 접수 정보·기준·열 대응표·CSV 헤더를 열 때부터 해당 방법의 열 연결을 설정하고 확인할 때까지 | `mapping_s` |
| ② 최초본 검토 | 최초 측정값을 열 때부터 첫 판정표와 예외 목록을 저장할 때까지 | `first_s` |
| ③ 수정본 재검토 | 수정 자료를 지급할 때부터 수정본 판정표와 추가·삭제·변경·미해결 목록 또는 전체 재검토 사유를 저장할 때까지 | `revised_s` |
| ④ 수동 검산·보정 | 각 제출 직후 원본 대조·계산 확인·오류 수정을 시작할 때부터 해당 판정표를 확정할 때까지 | `manual_first_s`, `manual_revised_s` |

④를 최초본과 수정본에 나누어 기록하면 수정본 검산에 든 시간을 ③과 함께 비교할 수 있다. 검산이 실제로 없었을 때만 해당 ④ 칸에 0을 입력한다. 중단, 환경 변경, 입력 거부, 미수행은 각각 `interrupted`, `incomparable`, `failed`, `unperformed`로 표시하고 관측하지 못한 칸은 비워 둔다. 누락값을 0이나 예상 시간으로 채우지 않는다. 외부 서비스 대기는 경과 시간에 포함한다.

- **Excel**. 제공된 기준·열 대응표로 새 통합문서에서 직접 검토한다. 기본 수식, 정렬·필터를 사용할 수 있다. 다른 방법의 판정·미리 만든 사례별 수식·AI 결과를 가져오지 않는다.
- **Claude**. 한 세션마다 새 대화를 연다. 최초본에서 입력 네 파일과 [고정 프롬프트](templates/claude_prompt.ko.txt)를 그대로 사용한다. 수정본에서는 같은 대화에 수정 회차 파일 네 개를 첨부하고 같은 문구를 다시 사용한다. 모델·스킬 변경이나 추가 힌트가 필요하면 해당 세션에 `incomparable`을 기록한다. 원문 응답과 사용 환경을 로컬에 보관한다.
- **로컬 도구**. 같은 입력으로 패키지의 `review`를 최초본과 수정본에 각각 실행하고 `diff`로 비교한다. 각 회차의 `intake.json`에서 `--supplier`, `--lot`을 읽는다. 새 출력 폴더를 사용한다. 제공된 입력으로 명령이 실패하면 오류와 실제 경과 시간을 남긴다. [패키지 명령 예시](../README.md)
- **제출 동결**. 검토자는 두 판정표와 근거(헤더를 제외하고 1부터 세는 데이터 행, 또는 누락 기준의 특성·표본), 예외 행, 비교 결과와 수동 보정 내용을 남긴다. 진행자는 세션별 원본 결과를 로컬 `evidence/` 아래 서로 다른 파일로 보관한다. 통합문서·프롬프트/응답·로컬 JSON과 시간 기록을 해당 세션별 압축 파일로 묶을 수 있다. `sessions.csv`의 `evidence_file`에 수집 폴더 기준 상대경로를 적는다.
- **공통 판정 시트**. 진행자는 정답 공개 전에 확정된 두 판정표를 `decisions.csv`의 미리 배정된 각 행에 옮긴다. 허용 상태는 `in_tolerance`, `out_of_tolerance`, `missing`, `undetermined`다. 로컬 도구의 `cannot_evaluate`는 `undetermined`로 옮긴다. 경고는 `warning`에 `yes/no`로 기록한다. 공차 내라도 공급사 판정과 다르면 경고가 있을 수 있다. 응답이 생략한 표본은 판정 불가로 대신 채우지 않는다. 이 경우 세션을 `incomparable`로 남긴다. 단순 전사는 측정 구간 밖에서 진행한다.

## 채점과 판정

진행자가 실제 관측과 환경 일치를 확인한 세션에만 `complete`를 적는다. 모든 제출을 동결한 뒤 `environment.json`의 `collection_origin`에 `observed_human_sessions`를 입력하고 다음 명령을 실행한다.

```sh
python3 benchmarks/scripts/pilot.py summarize benchmarks/results/run-01
python3 -m unittest discover -s benchmarks/tests -p 'test_*.py'
```

집계기는 배정표, 배포 자료 지문, 모형·도구 버전, 세션별 제출 파일, 네 구간의 시간, 두 회차 전체 표본 응답을 확인한다. 누락·중복·비교 불능 자료가 있으면 오류로 종료한다. 채점 시 기계 벤치마크도 다시 실행한다. 검토자 이름, 세션별 시간, 원문 응답과 개인별 성적을 출력하지 않는다.

| 판정 기준 | 사전 정의 |
| --- | --- |
| 기계 품질 | 10건 × 두 제출본이 모두 채점되어야 한다. 잘못된 정상 0건, 정상 오경고율 ≤ 5%, 모든 경고의 근거 도달률 100%, 제출본마다 동일 입력 5회 반복 일치 100%를 확인한다. 사례별 검토·비교 정확성은 기계 채점 결과에서 확인한다. 실제 로컬 도구를 사용한 검토자 2명의 확정판도 잘못된 정상 0건, 정상 오경고율 ≤ 5%를 모두 충족해야 한다. |
| Excel 대비 업무 시간 | 검토자 × 사례 20쌍을 동일하게 사용한다. 세션의 수정본 완료 시간은 ③ + 수정본 ④다. 단축률은 `100 × (1 − 로컬 완료시간 중앙값 / 비교 방법 완료시간 중앙값)`이다. 반올림 전 Excel 대비 ≥ 30%여야 한다. 방법별 ①·②·③·④와 전 구간 합계의 중앙값도 별도로 공개한다. |
| Claude 대비 차별성 | 동일한 두 검토자·두 회차·모든 표본의 확정판을 독립 정답표로 채점한다. 로컬의 잘못된 정상 건수가 더 적거나, 정확도가 같고 수정본 완료 시간 중앙값이 ≥ 20% 짧아야 한다. 동등 정확도는 잘못된 정상 수, 정상 오경고 수, 4개 상태의 정확 일치 수가 모두 같은 경우로 고정한다. |
| Claude 시험 불가 | 배정 전에 실제 시험 불가 근거를 확인하고 Excel과 로컬 방법의 수집을 완수하면 기계 품질·로컬 실측 품질·Excel 시간 조건으로 판정한다. Go일 수 있으나 Claude 상대 성능은 미검증이다. |
| 현장 오프라인 예외 | 실제 업무에서 오프라인 실행이 필수라고 독립 확인한 기록은 Claude 조건을 대체할 수 있다. 비교 미실시 상태에서 Claude 대비 우위를 주장할 수 없다. |

정답상 초과·누락·판정 불가인데 정상으로 기록한 항목을 잘못된 정상으로 센다. 정상 오경고의 분모는 정답상 정상이며 정당한 경고 사유가 없는 항목이다. `GO`는 필수 근거와 기준을 모두 충족했을 때, `NO_GO`는 완전한 실측에서 기준 미달이 확인됐을 때 기록한다. 기계 측정이 누락되거나 계획한 Claude 세션의 수집을 마치지 못하면 `PENDING`으로 남긴다. 배정했으나 실시하지 않은 Claude는 **미실시**, 사전에 확인한 불가·오프라인 예외의 상대 측정값은 **해당 없음(N/A)** 으로 표기한다. 두 경우 모두 상대 측정값을 만들지 않는다.

원자료와 중간 집계는 전부 Git에서 제외하는 `benchmarks/results/`의 수집 폴더에 둔다. 사람이 확인한 비식별 집계와 판정 근거만 `results/pilot_summary.ko.md`에 옮긴다. Track 2C의 XLSX·매핑 보조·제안서 실측 반영은 Go 이후에 착수한다.
