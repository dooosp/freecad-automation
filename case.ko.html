USB 허브 시험판 — 설계 변경과 검증을 연결한 사례

오른쪽 홀 두 개를 10 mm 옮기고, 저장된 STEP·도면에서 변경과 유지 조건을 다시 확인했다. 실제 USB 허브를 측정한 장착 설계가 아니라, CAD 자동화와 검증 방법을 보여주는 합성 소프트웨어 사례다.

문제와 판단

홀 배치를 바꾸면 모델뿐 아니라 도면과 검증 결과도 함께 갱신해야 한다. 파일 생성 성공이나 외곽 크기·체적만으로는 홀 중심이 올바르게 이동했는지 판단할 수 없다. 이 사례에서는 고정할 형상과 바꿀 형상을 먼저 나누고, 내보낸 STEP을 다시 읽어 네 홀의 지름과 중심을 측정했다.

시험 가정은 책상 고정점과 기존 허브 브래킷을 연결하는 평판이다. 142 × 74 × 4 mm, Ø5.2, 이동량 10 mm는 모두 시험용 가정이다. 실측·제조사 사양·강도 계산에서 얻은 값이 아니다. 좌표 원점은 위에서 본 판의 왼쪽 아래, X는 오른쪽, Y는 위쪽, Z는 두께 방향이며 단위는 mm다.

결과와 근거

2026-09-25, Node 25.8.0 / FreeCAD 1.1.3의 실제 런타임에서 아래 흐름을 재현했다. 기준 소스 4dba0d32fe1b10f2266f27501165e56df9f943af에 Studio 품질 요약·JSON 입력·STEP 검출 진입점 수정을 적용한 상태로 검증했다. 수정과 사례 소스는 codex/studio-quality-summary-fix 브랜치의 커밋으로 관리한다.

STEP 비교 허용값 0.00001 mm, SVG 반올림 비교 허용값 0.03 mm는 소프트웨어 수치 검사 한계다. 제조 공차가 아니다. SVG 검사는 이 직선 외곽·원형 홀 사례에 한정된다.

Studio는 이전에 실행 완료 뒤 실제 품질 실패를 요약에 보여주지 못했다. F01 수정 후에는 실행 완료 / 품질 실패 / WIDTH 근거 부족 / 실제 SVG 주요 결과를 표시한다. 2026-09-24에 실제 브라우저의 한국어·영어 화면과 npm test를 검증했고, 2026-09-25에는 해당 7개 수정 파일의 SHA-256이 그대로임을 확인했다. 이 수정은 아직 master에 반영되지 않았다.

STEP 특징 검출 진입점을 수정해 원래 review-context CLI에서 네 Ø5.2 홀을 얻었다. 일반 모듈 import는 실행하지 않으며, 실제 입력 형상 오류 때의 metadata fallback은 유지한다. JSON 입력은 공용 설정 파서·정규화를 사용하도록 연결했다. 후속 조치와 확인 범위에 수정·검증 근거를 정리한다.

변경 영향과 미완료 검사 계획

합성 요구사항에 같은 USB-HUB-PLATE-SIM 부품과 17개 특성 ID를 정의했다. 원본 CAD 입력을 보존하고 비교용 사본에 name·부품·패키지·리비전·치수 요구사항을 명시한다. name도 기존 비교 계약의 부품 ID 별칭이므로 A/B에서 통일한다. 형상은 바꾸지 않고 각 요구값을 실제 저장 STEP 측정값과 대조한 뒤 원래 CLI를 호출한다. 모델·원본 설정·비교 설정의 SHA-256도 남긴다.

자동 비교는 판과 D홀의 9개 특성을 영향 없음으로 분류한다. 변경 계획에는 H홀의 X·Y·지름과 두 종속 치수 8개가 들어간다. Y·지름의 명목치는 유지되지만 같은 홀의 위치가 바뀌어 후속 확인에 포함된다. 추가 1개는 자동 검출한 홀 패턴이다. 이 패턴의 ID는 형상 내용에 따라 바뀌며 명시적 요구사항과 연결되지 않아 revision_impact_characteristic_unresolved로 남는다. 일반적인 BREP 특징 동일성 매칭을 완성했다고 주장하지 않는다.

공차와 검사 방법은 모든 계획에서 null이다. 계획 상태 review_required는 올바른 미완료 상태이며, 사람 검토·별도 승인이 필요한 상태다. field_authority의 authoritative_released_requirement는 기존 CLI가 --requirements 입력에 사용하는 분류명이다. 이 입력은 production_trust: false인 합성 시나리오이며 실제 제조 사양이 승인·릴리스됐다는 뜻이 아니다. 검사값·판정은 작성하지 않았다.

설명할 수 있는 역량과 한계

이 사례로 설명할 수 있는 것은 파라미터 변경, 유지 조건 정의, CAD 출력 재측정, 도면과 형상의 불일치 감지, 실패 결과의 사용자 전달이다. 후속 공학 검토에서는 홀 패턴의 대응, 모서리 여유, 단순화한 하중 관계와 실제 DFM·보고서 재실행을 다룬다. 실제 체결·간섭·하중·재질·제조 공차·생산 적합성은 검증하지 않았다. 실제 허브 장착 설계나 제조 승인으로 제시하지 않는다.

기존 입력의 part/revision 연결 문제는 별도 합성 입력을 준비해 해결했다. 생성된 변경 영향·계획은 검토 자료이며 완료된 검사나 승인 기록이 아니다. 이 사례를 기존 canonical 제조 준비 패키지로 등록하거나 검사 증거를 첨부하지 않았다. USB 사례에 허용되지 않은 --proof-lineage 경로도 사용하지 않았다.

AI 활용 기록은 Codex를 통한 재현·진단·보조 검사·수정·검증·문서화다. 사용자와 Codex의 기여 기록에 확인된 역할을 구분한다. 제품 내 유료 AI API 실호출은 수행하지 않았다. 사용자의 개인 코드 기여나 설계 의사결정·이해도는 이 실행 기록으로 확인할 수 없으므로, 본인이 수행한 범위만 면접에서 설명해야 한다.

재현과 시연

저장소 의존성과 FreeCAD를 준비한 뒤 저장소 루트에서 실행한다.

매번 새 output/usb-hub-portfolio-* 폴더를 만든다. case-result.json, measurements.json, commands.json, A/B STEP·SVG·품질 JSON과 revision-review/의 변경 영향·검사 계획이 근거다. 생성물은 output/에 보관하며 소스로 커밋하지 않는다. 열람용 묶음은 이 결과의 도면·측정값·계획과 실제 검증 화면을 모은 설명 자료다.
